# Remotwerk

두 사람(연인)이 함께 쓰는 **데스크톱 캐릭터 앱**. 각자 자신의 캐릭터를 고르면,
내 캐릭터가 상대의 화면 위에 상주하며 살아 움직이고, 상대의 캐릭터가 내 화면 위에
상주한다. 나는 리모컨으로 간단한 동작을 발사하고, 그 동작은 상대 화면에 있는
내 캐릭터가 수행한다.

메신저가 아니다. 텍스트가 아니라 **몸짓으로, 답장을 요구하지 않는 낮은 대역폭의
신호**를 주고받는 현존(presence) 아바타다. 업무 중 곁눈질 한 번에 읽히는 작고
귀여운 신호가 핵심 경험이다.

> 이 저장소는 **코어 앱(Prompt A)** 범위다. 캐릭터 업로드 및 인앱 리깅 도구는
> 별도(Prompt B)로 구현한다.

## 핵심 설계 원칙 (위반 금지)

1. **비침습성** — 오버레이는 작업 영역을 가리지 않고, 캐릭터 밖 영역은 클릭을 통과시킨다.
2. **무압박** — 읽음/응답 표시를 만들지 않는다. 신호는 도착까지만, 봤는지는 알리지 않는다.
3. **곁눈질 가독성** — 신호 하나가 하나의 또렷한 동작으로 즉시 읽힌다.
4. **상대 상태 비감시** — 화면 속 캐릭터의 자율 생활은 상대의 접속·활동을 반영하지 않는다.

## 실행

```bash
npm install
npm start
```

- Electron(Windows·macOS)에서 동작. 투명·항상 위·클릭 통과 동작은 OS별 세부가
  다르므로 각 플랫폼에서 확인이 필요하다.
- 최초 실행 시 **설정 창**이 뜬다. Firebase 설정을 비워 두면 **로컬 데모 모드**로
  실행되어, 같은 PC 안에서 리모컨→오버레이 흐름을 끝에서 끝까지 확인할 수 있다.

### 조작

| 기능 | 방법 |
|------|------|
| 리모컨 열기 | `Ctrl/Cmd + Shift + R` 또는 트레이 메뉴 |
| 즉시 숨김/복원 (보스키) | `Ctrl/Cmd + Shift + H` |

## 동작(신호) 목록

**능동 8개 (리모컨으로 발사)** — 라디얼 12시부터 시계방향:

1. 🥱 지루해 뒹굴기
2. 🍑 엉덩이 트월킹
3. 🙌 무릎 꿇고 좌절
4. 🩰 피겨 턴·발레 점프
5. 🚪 자리비우기(사라짐 — 복귀는 다음 신호가 트리거)
6. 🥰 다가와 얼굴 부비기
7. 😤 분노 오오라
8. 🤷 W 팔 으쓱

**자율 생활 2종 (신호 아님, 로컬 반복)** — 😐 멍때리기 · 🚶 돌아다니기.
전송되지 않고 히스토리에도 남지 않는다.

> 11개 동작의 안무 값(키프레임)은 각 동작의 "키 자세" 설명을 바탕으로 만든
> **저프레임 플레이스홀더**다(`src/renderer/shared/animations.js`). 이후 아트/안무에
> 맞춰 다듬어 교체한다.

## 구조

```
src/
  main/
    main.js         # 창 관리(오버레이·리모컨·히스토리·설정), 전역 단축키, 트레이
    preload.js      # 렌더러↔메인 브리지(설정/창 제어/클릭 통과)
    config.js       # userData/config.json 저장소(페어링·캐릭터·집중 모드)
  renderer/
    overlay/        # 상대 캐릭터 상주 + 신호 라이브 재생 + 자율 생활 + 드래그
    remote/         # 원형 8버튼 라디얼 리모컨
    history/        # 오늘 받은 신호 목록
    settings/       # 페어링 코드/캐릭터 선택((+) 리깅 도구)/Firebase 설정
    rigger/         # 리깅·업로드 도구(大자 5조각 정합 → 커스텀 캐릭터) — Prompt B
    viewer/         # 동작 뷰어(디버그) — 캐릭터 골라 동작 즉시 재생
    shared/
      skeleton.js   # 이족 골격(상세 bipedal + 5조각 bipedal5)
      gestures.js   # 동작 메타데이터(id·이름·아이콘)
      animations.js # 골격별 11개 키프레임 시퀀스(플레이스홀더)
      engine.js     # 골격 기반 재생 엔진(트랙 보간, animSource 리매핑, fit 렌더)
      presets.js    # 프리셋 캐릭터 로더
      characters.js # 프리셋+커스텀 통합 해석기(번들→리그)
      transport.js  # 신호 송수신/히스토리 + 커스텀 캐릭터 공유(Firebase Storage)
  assets/presets/   # 프리셋 에셋 포맷(rig.json) + 포맷 문서
```

## 애니메이션 엔진

- 골격은 **이족(bipedal)** 으로 고정. 각 골격은 고정된 관절 슬롯(머리·몸통·좌우
  팔·좌우 다리)을 가진다.
- 애니메이션은 캐릭터가 아니라 **골격**에 대해 만든 키프레임 시퀀스다. 같은 골격이면
  어떤 캐릭터를 올려도 같은 시퀀스가 그대로 적용된다.
- 엔진은 희소 키프레임을 **본별 트랙**으로 펼쳐 선형 보간한다(회전/오프셋). 가시성·
  좌우반전(피겨 턴 인상)은 계단 보간, 오오라 강도는 별도 레이어로 표현한다.

## Firebase 데이터 모델

계정 없이 공유 **페어링 코드**로 두 사람을 한 방에 묶는다(Realtime Database).

```
rooms/{code}/
  members/{userId}: { characterId, joinedAt }
  signals/{pushId}: { from, gestureId, ts }
```

- 신호 하나는 `{ from, gestureId, ts }` 로 매우 가볍다.
- **온라인**: 상대 클라이언트가 실시간 수신해 내 캐릭터로 라이브 재생 + 히스토리 기록.
- **오프라인**: 신호는 Firebase에 남아 있다가, 상대가 다음에 앱을 켰을 때
  **히스토리에만** 표시(라이브 재생 안 함).
- 판별: 클라이언트는 실행 시작 시각을 기록하고, 수신 `ts` 가 그 이후면 라이브,
  이전이면 히스토리로 처리한다.
- 히스토리는 상대가 보낸(from ≠ 나) **오늘(KST)** 신호만. 로컬 자정(KST)에 비운다.
  하루 이상 지난 신호는 베스트 에포트로 정리한다.

### 프로젝트 설정 (remotwerk-aa0d2)

앱은 기본으로 Firebase 프로젝트 `remotwerk-aa0d2` 에 연결된다(설정은
`src/main/config.js` 의 기본값). 두 사람이 앱을 켜고 **같은 페어링 코드**만 넣으면 묶인다.

> 웹 API 키는 클라이언트 공개용이라 커밋해도 안전하다(비밀이 아님). 실제 접근 보호는
> **Realtime Database 보안 규칙**이 담당한다.

콘솔에서 한 번 해둘 것:

1. **Realtime Database 생성** — Firebase 콘솔 → Build → Realtime Database → 인스턴스 생성.
2. **databaseURL** — 인스턴스는 **싱가포르(asia-southeast1)** 리전으로 생성되어 있고,
   `config.js` 의 `databaseURL` 이 이미 실제 값
   (`https://remotwerk-aa0d2-default-rtdb.asia-southeast1.firebasedatabase.app`)으로 설정되어 있다.
3. **보안 규칙** — 계정 없이 페어링 코드로만 쓰므로, 최소한 아래처럼 `rooms` 하위만
   허용하는 규칙을 권장(둘만 아는 코드가 사실상의 열쇠):
   ```json
   { "rules": { "rooms": { "$code": { ".read": true, ".write": true } } } }
   ```
   (더 조이려면 Firebase 익명 인증을 붙여 `auth != null` 조건을 추가 — 범위 밖.)

### Firebase 없이 검증 (로컬 데모)

설정에서 Firebase를 비워 두면 `BroadcastChannel` 기반 **로컬 루프백**으로 동작한다.
리모컨에서 보낸 신호가 '상대'로서 내 오버레이에 되돌아와 재생되고 히스토리에 쌓인다.
아트·안무·상호작용을 실제 Firebase 없이 끝에서 끝까지 확인하기 위한 모드다.

## 커스텀 캐릭터 — 리깅·업로드 도구 (Prompt B)

사용자가 직접 이미지를 올려 자신의 캐릭터를 만드는 인앱 도구. 캐릭터 선택 UI의
**(+) 버튼**(설정 창) 또는 트레이 "캐릭터 만들기"로 연다.

- **大자(spread) 가이드 · 5조각**: 몸통+머리 / 좌팔 / 우팔 / 좌다리 / 우다리. 관절은
  **어깨·골반만**(팔꿈치·무릎 없음), 머리는 몸통에 포함(골격 `bipedal5`). 자유 분할이나
  관절 점 찍기는 없다 — 부위별 투명 PNG 5장을 올려 크기·위치·회전·z로 가이드에 맞춘다.
- **가이드 비율 조정**: 몸통 길이·너비, 어깨 높이/너비, 골반 너비, 팔·다리 길이/두께를
  슬라이더로 바꿔 캐릭터 체형(짧은 몸통·긴 다리 등)에 가이드를 맞춘다. 이 비율은 번들의
  `proportions` 로 저장되어, 관절 위치가 바뀐 채로 상대 화면·애니메이션에 동일 적용된다.
- **동작 재사용**: 새 동작을 만들지 않는다. 코어의 고정 세트(능동 8 + 자율 2)를 그대로
  재생한다. 엔진이 각 조각을 어깨·골반 트랙(`animSource`)에 리매핑해 근사 재생한다.
- **5조각 근사(중요)**: 3 무릎 꿇기→다리 회전+몸통 하강으로 주저앉는 인상, 6 얼굴
  부비기→몸통 전체 기울임, 8 W자→**팔꿈치가 없어 곧게 든 팔 + 으쓱(W 형태 상실)**.
  1·2·4·5·7 은 거의 온전. 7 오오라는 리그와 무관한 오버레이 레이어라 항상 정상.
- **저장 포맷**: 프리셋과 **동일**(부위 이미지 + 리그 JSON). 같은 엔진이 구분 없이 로드한다.
  이미지는 업로드 시 다운스케일(한 변 ≤512px)하고 번들 총용량 상한(≈2MB)으로 관리한다.
- **파트너 공유**: 내 캐릭터는 상대 화면에 그려지므로, 커스텀 번들을 **Firebase Storage**
  (`rooms/{code}/characters/{userId}.json`)에 올리고 RTDB `members/{userId}.characterRef`에
  참조를 기록한다. 상대 클라이언트는 characterRef를 감지하면 번들을 내려받아 캐시·렌더한다.
  (로컬 데모 모드에서는 Storage 없이 config 에 저장해 오버레이가 바로 반영한다.)

### Storage 설정 (remotwerk-aa0d2)

- 버킷 `gs://remotwerk-aa0d2.firebasestorage.app` (us-central1), 설정 값은 config 의
  `storageBucket` 로 이미 연결되어 있다.
- 현재 **테스트 모드 규칙**(30일 공개 읽기/쓰기)이라 바로 업로드/다운로드가 된다.
  기간 만료 전, `rooms/{code}/characters/**` 만 허용하는 규칙으로 조여 두는 것을 권장 —
  저장소 루트의 **`storage.rules`** 파일을 콘솔(Storage → Rules)에 붙여넣으면 된다.

## 오버레이 · 멀티 모니터

오버레이 창은 **모든 디스플레이를 합친 가상 데스크톱 전체**를 덮는다(음수 좌표 포함).
덕분에 캐릭터를 드래그하거나 자율 이동으로 **모니터 경계를 넘어** 옮길 수 있다.
모니터를 추가/제거하거나 해상도를 바꾸면 오버레이가 자동으로 다시 맞춰진다.

## 범위 밖 (Non-goals)

동작 조합/수식자, 커스텀 암호, 공유 사전, 사운드, 라벨 토글, 클릭 조회, 리액션
어휘, 상대의 접속·활동 상태 표시. 리깅 도구도 자유 올가미 분할·관절 점 찍기·팔꿈치/무릎
관절·사족 골격·사용자 정의 동작·표정 교체는 다루지 않는다(大자 5조각 정합으로 대체).
