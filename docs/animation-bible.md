# Remotwerk Animation Bible — 물개(`char_seal`)

이 문서는 **그림을 그리는 사람과 재생하는 코드가 함께 지키는 계약**이다.
여기서 정한 캔버스·기준점·타이밍·파일명을 지키면, 그림만 갈아 끼워도 앱이 그대로 돈다.

기준 캐릭터는 물개 하나다. 다른 캐릭터에 복사할 것은 **연기 순서·타이밍 의도·접지 규칙**이고,
포즈와 보폭은 복사하지 않는다(물개의 짧은 지느러미 보폭을 사람 캐릭터에 쓰면 어색하다).

## 2. 캔버스와 기준점

모든 프레임은 **같은 캔버스, 같은 기준점**을 쓴다. 이게 어긋나면 재생할 때 캐릭터가 튄다.

| 항목 | 값 |
|---|---|
| 캔버스 | **512 × 512 px**, 투명 배경 PNG |
| 기준점(anchor) | 캔버스 좌표 **(256, 470)** = 두 발 사이 바닥 중앙 |
| 바닥선 | y = 470. 서 있는 프레임에서 **발바닥이 이 선에 닿는다** |
| 기본 키 | 정지 자세에서 정수리 y ≈ 130 → **캐릭터 높이 340px** |
| 좌우 여백 | 지느러미를 최대로 벌려도 좌우 각 40px 이상 남긴다 |
| 위 여백 | 점프 정점에서도 캔버스 위에 닿지 않아야 한다(정점은 y ≈ 60 까지) |
| 표시 배율 | `displayScale` = 논리픽셀 ÷ 캔버스픽셀. 물개는 **0.7059**(340px → 240 논리픽셀) |

> `displayScale` 은 **리그로 그리던 크기와 맞춘 값**이다. 이게 어긋나면 스프라이트가
> 있는 캐릭터만 크기가 달라 보인다(실제로 처음엔 절반 크기로 나왔다).
> 새 아트를 그릴 때 캐릭터 높이 340px 을 지키면 이 값을 그대로 쓸 수 있다.

- 점프처럼 발이 뜨는 프레임은 **기준점을 옮기지 않는다.** 캐릭터를 캔버스 안에서 위로 그린다.
  (기준점을 옮기면 앱이 이동으로 오해한다.)
- 화면 이동(걸어서 앞으로 나아가기)은 **그림에 넣지 않는다.** 앱이 좌표로 옮긴다.
  걷기 프레임은 **제자리걸음**으로 그린다. → 5절 "이동" 참고.

## 3. 연기 규칙

모든 능동 신호는 네 박자를 지킨다.

1. **준비(anticipation)** — 주요 동작과 **반대 방향**으로 살짝. 전체의 15~20%.
2. **주요 동작(action)** — 가장 크고 빠른 구간. 실루엣이 여기서 결정된다.
3. **반동(overshoot/recoil)** — 지나쳤다 되돌아오는 한 프레임. 없으면 뻣뻣해 보인다.
4. **안정(settle)** — 대기 자세로 수렴. **마지막 프레임 = 대기 1번 프레임**(4절 규칙).

곁눈질로 0.5초에 읽혀야 하므로, 실루엣이 서로 겹치는 자세는 쓰지 않는다.

### 접지(발 디딤)
- 바닥에 닿은 발은 **그 구간 동안 캔버스 안에서 움직이지 않는다.** 미끄러지면 실패.
- 무게중심(골반)은 디딘 발 쪽으로 넘어간다. 상체는 **한 박자 늦게** 따라온다.
- 발이 바뀌는 순간에만 반대 발이 움직인다.

## 4. 클립 접합 규칙 (가장 중요)

앱은 클립을 **끊고 이어 붙인다**. 그래서 다음 두 가지를 강제한다.

- **루프 클립**: `frames[0]` 과 마지막 프레임의 **다음 자세**가 같아야 한다.
  즉 마지막 프레임에서 첫 프레임으로 넘어갈 때 튀지 않아야 한다.
- **일회 클립(신호)**: **마지막 프레임 = `idle` 의 0번 프레임과 동일**해야 한다.
  이 자세를 **접합 자세(neutral pose)** 라 부른다. 모든 클립은 접합 자세에서 시작해
  접합 자세로 끝난다. 예외는 `turn_*` 계열(뒤돌기 전용, 3.2절)뿐이다.

접합 자세(물개): 정면, 두 발 바닥, 지느러미 아래로 28° 벌림, 몸통 수직, 눈 감고 웃음.

- **중단 가능 구간(cancelable)**: 각 클립은 "여기부터는 새 신호를 받아도 된다"는
  프레임 번호를 메타데이터에 적는다. 보통 반동이 끝난 뒤부터.
- 중단이 허용되지 않는 구간에서 신호가 오면 **버리지 않고 큐에 1개만 보관**한다.

## 5. 이동(locomotion)

**그림에 넣는 이동과 코드가 하는 이동을 겹치지 않는다.**

- 걷기 클립은 제자리걸음이다. 캐릭터가 캔버스 안에서 앞으로 나아가지 않는다.
- 대신 메타데이터에 **`stepAdvance`(한 걸음이 나아가는 논리픽셀)** 과
  **각 발이 바닥에 닿는 프레임 구간**을 적는다.
- 앱은 걸음 주기에 맞춰 화면 좌표를 **연속으로** 움직인다.
  `속도 = stepAdvance / 한 걸음 시간`. 그래서 발이 미끄러지지 않는다.
- 방향은 좌우 반전으로 만든다(`flip`). 반전 전환에는 `turn_*` 클립을 끼운다.

물개 기준값: 한 걸음 `stepAdvance = 26` 논리픽셀, 한 걸음 320ms → 약 81px/초.

## 6. 동작 목록과 프레임 예산

프레임 수는 **고유 그림 수**다. 재생 순서·유지 시간과는 다른 개념이며,
같은 그림을 여러 번 쓰는 것은 자유다(예: 걷기는 8장으로 좌우 대칭 왕복).

아래 표는 **실제로 만든 결과**다. 처음 잡은 예산과 다른 칸은 비고에 이유를 적었다
(예산은 답이 아니라 출발점이고, 재생 검사에서 튄 구간에는 사이 그림을 더 넣었다).

| 클립 | 고유 프레임 | 재생 장수 | 총 길이 | 루프 | 비고 |
|---|---|---|---|---|---|
| `idle` | 4 | 4 | 2400ms | ○ | 숨쉬기. 0번이 접합 자세 |
| `walk` | 8 | 8 | 1280ms (2걸음) | ○ | 제자리걸음. 접지 구간 명시 |
| `g_heart` (보고싶어) | 7 | 7 | 1460ms | × | 예산 6 → 7. 정점과 착지 사이가 33px 튀어 사이 그림 1장 추가 |
| `g_cheer` (신나) | 7 | 15 | 1300ms | × | 02~05를 3회 반복해 점프 3회를 만든다 |
| `g_droop` (지쳤어) | 11 | 11 | 2480ms | × | 예산 6 → 11. 무너짐·좌우 기욺 전환이 계단처럼 끊겨 사이 그림 5장 추가 |
| `turn_back` | 3 | 3 | 300ms | × | 정면→3/4→뒤 |
| `twerk_loop` | 8 | 8 | 960ms | ○ | 뒷모습. 지지발·골반·상체 지연 |
| `turn_front` | 3 | 3 | 300ms | × | 뒤→3/4→정면 |

고유 프레임 **51장**. 접합 자세(`idle/frame-00`)처럼 여러 클립이 똑같이 쓰는 그림은
내용 해시로 합쳐지므로 실제 파일은 **42개**다(`src/renderer/assets/clips/char_seal/`).

`g_twerk` 는 `turn_back` → `twerk_loop`×3 → `turn_front` 로 **조합**한다.
동작 ID(`g_heart`·`g_cheer`·`g_droop`·`g_twerk`)와 네트워크 의미는 그대로 둔다.

### 6.1 트월킹 연기 규칙
좌우로 몸 전체를 흔드는 것이 아니다. 다음이 읽혀야 한다.
- **지지하는 발은 고정**. 두 발 다 바닥에 붙어 있고 캔버스 안에서 안 움직인다.
- **골반이 먼저** 좌우+위아래로 8자를 그린다.
- **상체는 1~2프레임 늦게** 따라온다(지연이 없으면 통짜로 흔들리는 것처럼 보인다).
- 머리는 거의 고정. 흔들림의 대비 기준점이 된다.

## 7. 프레임별 유지 시간

- 기준 그리드는 **40ms**(25fps). 유지 시간은 40의 배수로 적는다.
- 빠른 구간(점프 정점 통과, 방향 전환)은 40~80ms.
- 느린 구간(준비, 안정, 숨쉬기)은 160~400ms.
- **정점과 착지에는 각각 프레임을 하나씩 더 준다.** 여기가 눈이 머무는 곳이다.
- 화면 갱신 빈도(60/120Hz)와 무관하게 **경과 시간으로** 재생한다.

## 8. 파일·폴더·메타데이터 규격

```
art/clips/<캐릭터>/<클립>/frame-00.png … frame-NN.png   # 512×512 투명 PNG
art/clips/<캐릭터>/<클립>/clip.json                      # 아래 스키마
src/renderer/assets/clips/<캐릭터>/<클립>/*.png          # 빌드가 복사(앱이 읽는 곳)
src/renderer/shared/clip-art.js                          # 빌드가 생성(경로·타이밍만)
```

`clip.json`:

```json
{
  "id": "walk",
  "character": "char_seal",
  "canvas": { "w": 512, "h": 512 },
  "anchor": { "x": 256, "y": 470 },
  "displayScale": 0.7059,
  "loop": true,
  "loopFrom": 0,
  "cancelFrom": 0,
  "stepAdvance": 26,
  "frames": [
    { "file": "frame-00.png", "dur": 160, "ground": ["L"] },
    { "file": "frame-01.png", "dur": 160, "ground": ["L", "R"] }
  ],
  "placeholder": true,
  "note": "임시 에셋인 경우 반드시 placeholder:true 와 사유를 적는다"
}
```

- `ground`: 그 프레임에서 바닥에 닿은 발(`L`/`R`). 이동 속도와 접지 검사에 쓴다.
- `cancelFrom`: 이 프레임부터 새 신호로 중단 가능.
- `placeholder`: 임시 에셋 표시. **앱이 화면에 표시하지는 않지만 검사 도구가 경고한다.**

파일명은 소문자·하이픈만. 프레임 번호는 2자리 0채움.

## 9. 승인 체크리스트

한 클립을 승인하려면 전부 ○ 여야 한다.

1. □ 모든 프레임이 512×512, 투명 배경, 기준점 (256,470) 일치
2. □ 서 있는 프레임의 발바닥이 y=470 에 닿음(±1px). 뜨는 프레임은 `air` 로 표시
3. □ 루프 클립: 마지막→첫 프레임 전환에 튐 없음
4. □ 일회 클립: 마지막 프레임 = `idle` 0번(접합 자세)
5. □ 접지 구간에서 디딘 발이 캔버스 안에서 움직이지 않음
6. □ 눈·코·수염·반바지 무늬가 프레임 간 흔들리지 않음(정체성 유지)
7. □ 외곽선 굵기 일정, 색이 팔레트 밖으로 나가지 않음
8. □ 실제 표시 크기(높이 220px)에서 동작이 읽힘
9. □ 준비·주요·반동·안정 네 박자가 있음
10. □ `clip.json` 의 `dur` 합이 6절 예산과 ±20% 이내

### 재작업 기준
- 1·2·3·4번 중 하나라도 × → **즉시 재작업**(앱에서 튄다).
- 5·6·7번 × → 재작업. 곁눈질에서 바로 티가 난다.
- 8·9·10번 × → 타이밍 조정으로 먼저 시도, 안 되면 재작업.

## 10. 지금 무엇이 진짜 그림이고 무엇이 임시인가

**중요**: 현재 저장소의 `art/clips/char_seal/*` 는 **임시 에셋**이다.
원본 5조각을 앱 엔진으로 자세만 잡아 구운 것이라, 새로 그린 연기 자세가 아니다.
`clip.json` 에 `placeholder: true` 로 표시돼 있고, 검사 도구가 이를 경고한다.

임시 에셋의 목적은 **재생 구조·타이밍·접지·전환을 실물로 검증**하는 것이다.
진짜 아트는 이 문서 8절 규격에 맞춰 그려서 같은 경로에 넣으면 코드 수정 없이 교체된다.
필요한 그림 목록과 제작 지시는 `docs/art-orders.md` 를 참고한다.
